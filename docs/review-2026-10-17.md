# Site, pipeline and UX review: prioritized issues (2026-10-17)

Three reviews of the current `main`: site code, pipeline code, and user experience and accessibility.
Criteria:
- Princeton University Library IT's [handbook](https://github.com/pulibrary/pul-it-handbook): the production
  application checklist, WCAG 2 AA, inclusive language and AI-usage norms
- current web practice: WCAG 2.2 AA, responsive design, performance and security

Every item was reproduced or checked against the code. Effort: **S** < half a day, **M** 1–3 days,
**L** more. Source IDs (S-/P-/U-) refer to the review notes.

**Priorities**
- **P0**: wrong published data, or something that blocks deployment. Fix first.
- **P1**: significant user impact, or a WCAG AA or Princeton-standard gap.
- **P2**: moderate.
- **P3**: polish.

## What is solid (don't churn)

- **Search core:**
  - fast (30–120 ms per query)
  - simplified and traditional characters match each other (郵政 = 邮政, 336 results, same ranking)
  - Chinese URL slugs are consistent
  - links work under the GitHub Pages path prefix
- **Security of displayed text:** transcription HTML is sanitized with a tight allowlist (attack payloads such as `img onerror`, `javascript:` links and `svg` are removed), templates escape by default, and user input can't reach a regular expression.
- **Accessibility and links:**
  - axe finds no violations on 8 of 11 page types in light and dark mode; text contrast passes elsewhere; target sizes pass
  - the internal link crawl found 0 broken links or anchors across 1,676 pages
  - external links are clearly marked
- **Pipeline:** harvest change detection, data keys, province assignment and moderation handling are correct, and no secrets are in git history.
- **Light, robust pages:** browse and home pages are static and light (16–67 KB) and work without JavaScript; machine-extraction caveats and links back to DPUL appear throughout.

## Suggested order

1. **P0 #1–2** (parser fixes, re-export, release v0.1.2), then **#4**.
2. **#3** (deploy from the release bundle) and **#14** (tests and CI). Both are needed before more changes land.
3. **P1 accessibility #7–10** (Princeton requires WCAG AA), then search correctness and robustness **#5–6**.
4. **P1 usability #11–13**, then **#15–16**.
5. P2 in order, with the About page (#17) early, because it addresses trust in machine-extracted text.
